# GC Shop · 쇼핑몰 관리 웹 애플리케이션

Express와 EJS, MySQL을 사용해 서버 렌더링과 관계형 데이터 처리를 학습하는 쇼핑몰 프로젝트입니다. 회원·상품·장바구니·구매·게시판 화면 및 관리 기능을 포함합니다.

## 기술과 구조
| 영역 | 구성 |
|---|---|
| 서버 / 화면 | Express 5, EJS |
| 인증 상태 | express-session, 선택적 MySQL 세션 저장소 |
| 데이터베이스 | MySQL · schema.sql |
| 라우팅 | router/ |
| 화면 처리·쿼리 | lib/ |
| 템플릿·정적 파일 | views/, public/ |

## 로컬 실행
현재 DB 설정은 `main.js`와 `lib/db.js`에 있습니다. 두 파일의 접속 설정을 같은 로컬 테스트 DB로 맞춰야 합니다. 기본 DB 이름은 webdb2026입니다.

1. MySQL에서 테스트 데이터베이스를 생성합니다.
2. `schema.sql`을 테스트 DB에 적용합니다. 테이블 생성 외에 ALTER 및 데모 계정 생성이 포함되므로 운영 DB에 적용하지 않습니다.
3. 의존성을 설치하고 서버를 실행합니다.

```bash
npm ci
npm start
```

접속 주소: http://localhost:3000

## 기능별 진입점
| 경로 | 기능 |
|---|---|
| /auth | 로그인·회원가입 |
| /person | 회원 관리 |
| /product | 상품 |
| /purchase | 구매·장바구니 |
| /board | 게시판 |
| /code | 분류 코드 |

## 데이터 모델
person(회원), product(상품), code(분류), cart(장바구니), purchase(구매), boardtype(게시판 유형), board(게시글)로 구성됩니다. EJS 렌더링과 SQL 조회·변경이 연결되는 흐름을 설명할 수 있는 학습 프로젝트입니다.

## 제출 전 보강 항목
현재 비밀번호를 평문 비교하는 로그인과 학습용 기본 계정이 포함됩니다. 운영용으로 배포하기 전 비밀번호 해싱 및 DB 컬럼 변경, 환경 변수 분리, CSRF 방어, 권한별 접근 검증이 필요합니다.
결제 상태 관리는 실제 결제 대행사 연동을 의미하지 않습니다.

## 확인 범위
소스와 스키마를 기준으로 작성했습니다. 실제 MySQL 연결 및 브라우저 시나리오 검증은 별도로 필요합니다.
